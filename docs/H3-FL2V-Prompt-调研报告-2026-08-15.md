## 1. 问题诊断 — EP02 Shot 11 Prompt 分析

### 1.1 用户反馈的核心问题

| 问题 | 严重度 | 具体表现 |
|------|--------|---------|
| 环境/物件描述过多 | 🔴 高 | "破庙内，篝火跳动映照土墙与椽梁"、"右手持碗，左手搭于膝上"、"碗内映出跳动的倒影"——这些由首尾帧参考图已提供，浪费 FL2V token budget |
| 缺少运镜语言聚焦 | 🔴 高 | 运镜描述被嵌在自然语言段落里而非独立结构，模型提取困难 |
| 身体动作描述不够具体 | 🟡 中 | "身体前倾，低头凝视"缺乏速度/力度/节奏修饰 |
| 17 个 shot 无对白/旁白 | 🔴 高 | 历史剧无叙事声音，观众理解门槛极高 |
| 光影描述过度 | 🟡 中 | "暖橘火光从左侧低角度照亮"——参考图光位已定，文字冗余 |

### 1.2 根本原因分析

当前 H3 Prompt 生成链路的问题在于 **prompt-template.ts 的约束规则与 FL2V 模型的特性之间存在语义错配**：

```
AICF Content Layer → LLM → H3 Structured Prompt → MiniMax H3 FL2VA API
                      ↑
              这里生成的 prompt 是"全量描述"思维
              ——把每一帧画面都当作从零建立的 T2V
              但 FL2V 的首尾帧已经提供了视觉锚点
```

**FL2V 的本质**：首帧 + 尾帧 → 模型插值中间过程。Prompt 的作用不是"描述画面"，而是**描述从 A 到 B 的过渡路径**。

## 2. 现有 H3 Prompt 工程体系全貌

### 2.1 架构总览

```
video-generate.ts (pipeline handler)
  ├─ 加载全量上下文 (EP/场景/角色/对白/服饰/BGM)
  ├─ resolveVideoProvider → MiniMax H3 API
  ├─ H3 Prompt Mode (默认) / Seedance (opt-out)
  └─ buildVideoPromptLLM()
      └─ h3/prompt-template.ts
          ├─ Layer 1: Content Assembly
          │   ├─ VIDEO SCRIPT (用户输入)
          │   ├─ CHARACTERS (只描述动作，不描述外貌)
          │   ├─ DIALOGUE SCRIPT (S1/S2 speaker ID 系统)
          │   ├─ FRAME ANCHORS (首尾帧 prompt 文本)
          │   ├─ SCENE (地点/光线/色调)
          │   ├─ EPISODE CONTEXT
          │   └─ AUDIO
          ├─ Layer 2: Constraint Rules
          │   ├─ 时间结构强制拆分 (10s → 0-3/3-6/6-10)
          │   ├─ 动作节拍 (每 2-3s 微动作节点)
          │   ├─ 对白格式 ((S1)说：<d>[中文] text</d>)
          │   ├─ 运镜 (含幅度+速度修饰)
          │   └─ 格式 (中文输出，无 markdown)
          └─ Layer 3: Guide
              └─ ROLE + TASK + PROCESS + KEY PRINCIPLES
```

### 2.2 当前约束规则的强项

- ✅ 时间分段强制拆分（防止 LLM 生成无结构的散文）
- ✅ 角色外观描述禁止（"只描述动作，不描述外貌"）
- ✅ 运镜幅度/速度修饰（`with small amplitude at slow speed`）
- ✅ Speaker ID 系统（(S1)/(S2) 对话者锚定）
- ✅ 动作节拍要求（每 2-3s 微动作）

### 2.3 当前约束规则的弱点

| 弱点 | 根因 | 影响 |
|------|------|------|
| **环境描述无限制** | Content Layer 传入了 sceneDescription / sceneLighting / sceneColorPalette → LLM 自然会复述 | Token 浪费；与参考图信息冲突 |
| **场景信息在 prompt 里冗余** | FRAME ANCHORS 传了首尾帧的 prompt 文本（含完整环境描述）→ LLM 二次写入 integrated_multimodal_description | 双倍浪费 |
| **物件描述可无限展开** | 无"禁止描述静态物件"的硬规则 → Shot 11 出现了"黑陶碗""篝火""椽梁""戒疤" | FL2V 不关心这些 |
| **缺少旁白/画外音引导** | 对白规则覆盖了画外音，但 system prompt 未主动建议"无对白镜头应补旁白" | EP02 这种无对话集完全哑巴 |
| **运镜嵌入自然语言** | "镜头以极小幅度极缓慢推近" 是好散文但不是好 prompt——模型对结构化运镜指令响应更好 | 运镜执行率不稳定 |

## 3. FL2V 模型特性调研

### 3.1 什么是 FL2V

**FL2V = First-Last-Frame-to-Video**，MiniMax H3 的四种基础模式之一：

| 模式 | 输入 | 输出 |
|------|------|------|
| T2VA | 纯文本 | 视频+音频 |
| I2VA | 1 张首帧图 | 视频+音频 |
| **FL2VA** | **首帧图 + 尾帧图** | **视频+音频（插值中间帧）** |
| L2VA | 1 张尾帧图 | 视频+音频（反向推理） |

MiniMax H3 是 33B DiT，Qwen3-VL-32B 编码器，原生 32kHz 立体声音频。API 管线包含 prompt enhancement → base generation → 2K upscale。

### 3.2 FL2V 的核心行为特性（来自官方文档/社区实测）

#### 3.2.1 模型真正关心什么

来自 DomoAI 官方指南 + Runware 指南 + atlascloud.ai 反向工程：

```
FL2VA Prompt 的有效作用域（按重要性排序）:
1. 从 Picture 1 到 Picture 2 的过渡路径 ← 核心
2. 运镜运动（类型 + 幅度 + 速度）       ← 模型执行率最高
3. 角色身体动作（具体物理变化）          ← 次高
4. 对白/语音（<d> 标签）                 ← 语言层独立处理
5. 环境变化（光位偏移、物体移动）        ← 有用但次要
6. 静态环境描述、物件细节                ← 几乎无用（参考图已定）
```

**关键洞察**：FL2V 的 prompt 本质上是"过渡指令"，不是"场景说明书"。

#### 3.2.2 官方最佳实践总结

**DomoAI 指南 (最全面的非官方教程)**：
> "A useful FL2VA prompt names the intermediate motion: camera travel, water position, light change, and shadow movement."

**Runware 指南**：
> "Ask for motion the frame already implies. Hair in a breeze, a blink, drifting mist, rising bubbles, a slow camera push."
> "Keep the last frame reachable from the first. The most reliable last frames are an edit of the first, changing state, light, or one element while holding the frame."

**Luma AI 指南**：
> "Concrete actions give H3 a path through time. Describe physical changes rather than abstract intentions."

**atlascloud.ai 反向工程 45 个官方 prompt**：
> 时间切片（每片一个独立动作）> 单一动作拉伸全时长
> 特定运镜词汇 + 幅度/速度修饰 > 自然语言运镜描述
> 明确拒绝某些运动 > 不提运动让模型自由发挥

#### 3.2.3 WAN 2.2 FLF2V 社区实践

WAN 2.2 作为开源 FLF2V 模型，社区形成了一套 prompt 框架：

```
Opening scene → Camera motion → Reveal / payoff
```

80-120 词最佳。身体动作词汇表已被社区验证：
- 速度: slowly, gradually, briskly, quickly, gently, softly, suddenly, sharply
- 动作: head turns, glances, arms raise, hands gesture, walks, strides, steps, leans in, steps back, spins, rotates

### 3.3 FL2V 与 T2V/I2V 的本质区别

| 维度 | T2V | I2V | FL2V |
|------|-----|-----|------|
| 视觉锚点 | 无 | 首帧 | 首帧+尾帧 |
| Prompt 角色 | 描述一切 | 描述从首帧后的变化 | 描述首→尾的过渡路径 |
| 环境描述 | 必须（无其他来源） | 部分必须 | **几乎不需要**（两帧已定） |
| 运镜优先级 | 中等 | 高 | **最高**（唯一叙事工具） |
| 角色外观 | 必须在 prompt 中锚定 | 参考图提供 | **参考图+两帧提供** |

## 5. 旁白/画外音系统调研

### 5.1 H3 原生能力

H3 的 FL2VA 模式**原生支持**画外音 (off-screen voiceover)：

```
(S1) says in an off-screen voiceover: <d>[Chinese] text</d> while her lips remain completely closed.
```

Speaker ID 系统:
- (S1)/(S2) 按首次出场顺序分配
- 同一 speaker ID 贯穿全视频保持音色一致
- 可以指定 voice description: `The narrator with a deep, measured voice (S1) says...`

### 5.2 EP02 的叙事需求分析

EP02 "皇觉寺与三年流浪"：朱元璋在皇觉寺出家 → 寺庙饥荒 → 被迫外出化缘三年流浪

这 17 个 shot 的特点：
- **大量独角戏/内心戏**：朱元璋的内心挣扎、饥饿、孤独、成长
- **几乎没有对话**：和尚之间、与施主之间几乎没有台词
- **视觉叙事为主**：需要观众从画面理解故事
- **历史背景缺失**：如果不了解元末饥荒/皇觉寺背景，画面抽象难懂

### 5.3 旁白策略建议

**三层声音系统**：

| 层次 | 声音类型 | 示例 | 占比 |
|------|---------|------|------|
| **L1: 历史旁白** | 第三人称叙事者，娓娓道来历史背景 | "元至正四年，淮西大旱，蝗灾蔽日。皇觉寺的粮仓，也在那个冬天见了底。" | 50% |
| **L2: 内心独白** | 朱元璋的画外音心声（offscreen voiceover） | (S1) says in an off-screen voiceover: <d>[Chinese] 这天地之大，竟无一处能让我吃上一口饱饭。</d> | 30% |
| **L3: 稀疏对话** | 少量功能性台词 | 住持："寺中无粮了，你自行下山化缘去吧。" | 20% |

**技术实现**：
- L1 旁白 → 用 (S0) 或 (Narrator) speaker ID，在所有 shot 中保持一致
- L2 内心独白 → 用 (S1) 朱元璋的 voice，标记 `offscreen voiceover`
- L3 对话 → 当前已有系统，只需补充角色台词

## 6. 优化建议方案

### 6.1 P0: Prompt Template 重构 — FL2V 专属约束规则

**目标**：将 prompt 生成从"全量描述"切换为"过渡路径描述"。

**修改文件**: `src/lib/ai/prompts/h3/prompt-template.ts`

**方案**：

```typescript
// ═══ 新增 FL2V 专属规则 ═══

// 1. 环境描述最小化
"【环境——只描述变化】"
"首尾帧已经锚定了场景的全部视觉元素（地点、光线、物件、建筑）。"
"禁止在 integrated_multimodal_description 中描述："
"  - 静态场景元素（破庙、篝火、土墙、椽梁、碗、窗等）——这些从参考图已可见"
"  - 静态光线条件（'暖橘火光从左侧低角度照亮'）——光位由首尾帧提供"
"  - 静态物件细节（'碗内映出跳动的倒影'）——除非这个物件在镜头中移动/变化"
"只描述：环境光的变化（如火焰忽明忽暗、云遮月导致光线变化）"

// 2. 运镜优先于环境
"【运镜——第一优先级】"
"FL2V 模型对运镜指令的响应率远高于环境描述。"
"每个时间段的第一句话必须是运镜动作："
"  格式：'镜头 [运动类型] [幅度修饰] [速度修饰]'"
"  例：'镜头极缓慢推近，小幅。' / '镜头静止。' / '镜头缓慢向右微平移。'"
"运镜写完后，才写角色动作。"

// 3. 身体动作白名单
"【身体动作——使用具体物理动词】"
"用这些动词描述动作：转头、抬眼、垂眼、握紧、松开、抬手、放手、迈步、退后、"
"  前倾、后仰、起身、坐下、跪地、站起、转体、眯眼、眨眼、张口、闭嘴"
"禁止抽象词：'陷入沉思' → 改为 '眼帘低垂，眉心微蹙'"
"禁止模糊词：'神情变化' → 改为 '眉头从紧锁渐转为舒展'"

// 4. 旁白/内心独白强制
"【声音——主动添加叙事声音】"
"如果该 shot 的对话台本为空或不完整，你必须主动为角色添加："
"  - 内心独白（朱元璋的 off-screen voiceover）"
"  - 或旁白（第三人称 narrator 的 off-screen voiceover）"
"每 3-5 秒至少一句声音内容。禁止无对白的纯默片 shot。"
"格式：(S1) says in an off-screen voiceover: <d>[Chinese] 文本。</d> while his lips remain completely closed."
```

### 6.2 P1: Content Layer 裁剪

**目标**：减少传给 LLM 的环境上下文量，防止 LLM 复述。

**修改文件**: `src/lib/ai/prompts/h3/prompt-template.ts` (buildContentLayer)

**方案**：

```diff
- // Scene
- if (input.sceneDescription || input.sceneLighting || input.sceneColorPalette) {
-   parts.push(`## SCENE`);
-   if (input.sceneDescription) parts.push(`Location: ${input.sceneDescription}`);
-   if (input.sceneLighting) parts.push(`Lighting: ${input.sceneLighting}`);
-   if (input.sceneColorPalette) parts.push(`Color palette: ${input.sceneColorPalette}`);
- }

+ // Scene — FL2V mode: only pass scene info if it CHANGES during the shot
+ // (e.g. moving from indoors to outdoors, fire flickering out)
+ // For static scenes, the first/last frames already provide this context.
+ // Keep scene info available in the pipeline's shot record for reference,
+ // but don't pass it to the LLM prompt for FL2V mode.
```

同样地，FRAME ANCHORS 段的 prompt 文本（`firstFrame.prompt` / `lastFrame.prompt`）可以考虑精简为只传角色和构图信息，不传环境细节。

### 6.3 P2: 旁白/对白自动生成层

**目标**：为无对话 EP02 自动生成叙事声音。

**新增模块**: `src/lib/ai/prompts/h3/narration-generator.ts`

**方案**：
1. 在 `video-generate.ts` 中，检测 shot 的 dialogues 数量
2. 如果 shot 的 dialogues 为 0 或仅 1 条（无实质对话），调用 narration generator
3. Narration generator 传入 shot 上下文（videoScript + EP description + characters）→ LLM 生成旁白/内心独白
4. 生成的旁白以 offscreen voiceover 格式注入 H3 prompt

**输入**:
```
EP 背景: 元至正四年，淮西大旱。皇觉寺粮尽，17岁的朱元璋被迫外出化缘，开始三年流浪。
Shot: 破庙内，朱元璋独自看着手中的黑陶碗，眼神茫然。
Shot 时长: 10s
```

**输出**:
```
旁白 (Narrator, offscreen): (S0) says in an off-screen voiceover: <d>[Chinese] 十七岁的朱元璋还不知道，这碗里的稀粥，将是他往后三年里最丰盛的一顿饭。</d>
内心独白 (S1 Zhu Yuanzhang, offscreen): (S1) says in an off-screen voiceover: <d>[Chinese] 我朱元璋，难道真要饿死在这破庙里？</d>
```

### 6.4 P3: 运镜结构化输出

**目标**：将运镜描述从自然语言散文中提取为结构化格式，提高模型执行率。

**方案**：在 integrated_multimodal_description 的时间段内，采用固定格式：

```
当前格式 (散文):
0-3s: 破庙内，篝火跳动...朱元璋身体前倾，低头凝视手中黑陶碗...
镜头以极小幅度极缓慢推近，聚焦碗沿与面部。

建议格式 (运镜优先):
0-3s: [Camera: push in, small amplitude, very slow]
角色: 朱元璋 上身缓缓前倾，低头，视线落在碗沿。右手指尖轻触碗边。
声音: (S1) says in an off-screen voiceover: <d>[Chinese] 连一口热粥，都成了奢望。</d>
```

这需要验证 H3 是否对 `[Camera:]` 前缀格式有更好的响应，还是纯自然语言运镜描述效果更好。建议 **A/B 测试**。

### 6.5 优先级矩阵

| 编号 | 优化项 | 难度 | 影响 | 风险 | 建议 |
|------|--------|------|------|------|------|
| P0 | FL2V 专属约束规则 | 中 (修改 1 文件) | 🔴 高 | 低 (约束规则变更，可回滚) | **立即实施** |
| P1 | Content Layer 裁剪 | 低 (删除/注释代码) | 🟡 中 | 低 | **立即实施** |
| P2 | 旁白自动生成层 | 高 (新 LLM 调用) | 🔴 高 | 中 (增加 LLM 调用成本/延迟) | **P0 后实施** |
| P3 | 运镜结构化输出 | 中 (改格式) | 🟡 中 | 中 (需验证模型响应) | **A/B 测试后决定** |
